# Krea 2 프롬프트 문법 조사 (2026-10-04)

조사 목적: Krea2 Turbo Prompt Studio 업그레이드의 기준값 확정.
확신도 표기: ✅ 공식 원문 직접 확인 / 🟡 제3자 자료(공식 아님) / ❓ 미확인.

## 1. 공식 근거 (✅ 공식 저장소 원문을 직접 받아 읽음)

출처: `krea-ai/krea-2` 저장소의 `README.md`, `docs/prompting.md`, `docs/expansion.txt` (raw.githubusercontent.com, 2026-10-04 수신).

### 1-1. 프롬프트 문법 — 공식은 이게 전부다
- "자연어 프롬프트를 쓰라." 긴 상세 프롬프트가 가장 좋지만, 짧은 프롬프트도 고품질이 나온다.
- **글자 렌더링은 렌더할 단어를 따옴표로 감싼다.**
- 터보는 최대 2k 해상도까지 가능하다.
- 긴 프롬프트가 필요하면 `expansion.txt`를 LLM의 시스템 프롬프트로 쓰라고 안내한다.
- **공식 문서에 가중치 문법, 네거티브 프롬프트 문법, 태그 문법, 고정된 구조 순서는 없다.**

### 1-2. 공식 예시 20개의 공통 패턴 (✅ 원문 예시에서 관찰, 규칙으로 명시된 것은 아님)
두 가지 형식이 섞여 있다. 둘 다 공식 예시다.
- **쉼표 구절형**: `3D rendered matte black designer toy figure, stylized round ..., studio lighting, solid vibrant blue background, high contrast minimal composition`
- **서술 문장형**: `A close-up portrait of a young East Asian woman with straight black hair... She wears... The background is a solid, striking crimson red. Soft, directional studio lighting...`
- 매체/스타일을 앞이나 첫 문장에 둔다(`3D rendered`, `vintage analog collage`, `close-up anime portrait of`, `A macro photograph`).
- 구체적 재질, 색, 구도(`extreme low-angle`, `high-angle wide perspective`, `shallow depth of field`), 조명(`soft directional studio lighting`, `golden hour`)을 구체 서술로 적는다.
- `masterpiece`, `8k`, `best quality` 같은 품질 태그는 공식 예시에 하나도 없다.

### 1-3. 공식 프롬프트 확장 규칙 (`expansion.txt`) — 이 프로그램의 설계 기준으로 가장 쓸모 있음
1. 충실성 우선: 원래의 피사체·행동·색·공간관계를 보존, 암시되지 않은 물체·인물·동물을 추가하지 않는다.
2. 파싱 쉬운 구조: 피사체별로 속성과 행동을 묶고, 포즈·상호작용·공간배치는 구체적으로 쓴다.
3. 스타일 계획은 내부에서만: 계획 태그나 래퍼를 출력에 넣지 않는다.
4. 글자: 정확한 문구를 쓰고 따옴표로 감싼다.
5. 과도한 구체화 금지: 입력이 뒷받침하지 않으면 옷·색·재질·장면 디테일을 지어내지 않는다.
6. 구조: 한 단락의 일관된 글. 불릿·JSON·마크다운 금지.
7. 이미 상세한 프롬프트는 다듬기만 한다.
8. 인물은 존엄하게 다룬다. 의복이 생식기와 친밀 부위를 덮는 것으로 가정한다.
9. 사용자가 지정한 매체(photo of, illustration of, painting of, sketch of, 3D render of 등)는 존중하고 다른 매체로 바꾸지 않는다.

### 1-4. 모델·샘플러 설정 (✅ README)
| | Raw | Turbo |
|---|---|---|
| 용도 | 베이스·LoRA 학습용 | 8스텝 증류, 일반 추론용 |
| steps | 52 | 8 |
| CFG | 3.5 | **0.0 (비활성)** |
| mu | — | 1.15 |
| 해상도 | 최대 1k | 1k ~ 2k |

- 공식 권장: **Raw로 LoRA를 학습하고 Turbo에서 적용**한다.
- **Turbo는 CFG가 꺼져 있어서 네거티브 프롬프트가 사실상 작동하지 않는다.** 이건 공식 문서에 네거티브 문법이 없다는 사실과 CFG 0.0 설정에서 도출한 추론이다(공식이 "네거티브 불가"라고 명시한 문장은 못 찾음).

## 2. 제3자 자료 (🟡 공식 아님, 신뢰도 낮은 순으로 사용)

- 텍스트 인코더가 Qwen3-VL(언어모델)이고 CLIP/T5가 아니라서 태그 나열보다 자연어가 낫다. 여러 블로그가 같은 설명을 한다. 공식 README의 "자연어 권장"과 방향은 일치하지만 인코더 구성은 공식 원문에서 직접 확인 못 했다. (ComfyUI 워크플로 자료에는 `qwen3vl_4b` 인코더 파일이 쓰인다.)
- 30~150단어가 효과적이라는 수치는 제3자 가이드의 값이다. 공식에는 길이 수치가 없다.
- 구조 순서 "주제+맥락+구도+조명+스타일+크롭" 같은 권장은 블로그마다 다르다. 공식 규칙이 아니라 관례다.
- `(키워드:1.5)` 가중치 문법은 **ComfyUI 커스텀 노드(Krea2PromptWeight)의 기능**이고 모델 고유 문법이 아니다. 해당 자료도 이걸 "Krea 2 네이티브가 아니다"라고 쓴다. 다른 자료는 "가중치 문법 미지원, 다시 서술하거나 LoRA 강도를 쓰라"고 한다.
- 캐릭터 LoRA 트리거는 모델 카드마다 위치 지침이 다르다. "주제 설명 앞쪽 근처", "맨 끝" 둘 다 보인다. 공식 규칙이 아니라 각 LoRA 제작자의 권고다.
- 인물이 4~5명을 넘으면 인물별 속성 충실도가 떨어진다는 보고가 있다(제3자 노드 문서).

## 3. 현재 프로그램(v10.0.2)과 조사 결과의 대조

- ✅ 품질 태그(`masterpiece`, `8k`, `best quality`)는 본체 코드에 없다. 공식 방향과 일치.
- ✅ 재질·조명·카메라를 구체 서술로 넣는 설계는 공식 예시 방향과 일치.
- ⚠️ **LoRA 트리거를 항상 "첫 토큰"으로 출력**하는 규칙은 공식 근거가 없다. LoRA별 모델 카드 지침(앞/끝)이 갈리므로, 사용자가 LoRA별로 위치를 고를 수 있게 하는 편이 안전하다. (확인 대상, 변경은 승인 후)
- ⚠️ 프로그램이 만드는 문장 구조(구절형인지 서술형인지)와 길이를 공식 예시 기준으로 점검할 필요가 있다.
- ⚠️ 글자 렌더링(따옴표) 입력 경로가 있는지 확인 필요.
- ⚠️ 네거티브 프롬프트 기능이 있다면 Turbo(CFG 0)에서 무효라는 점을 UI에 표시할지 검토.
- 위 항목은 본체 3,620줄을 통독하지 않고 grep으로만 확인한 것이라 전수 점검이 아니다.
