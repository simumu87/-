# 본체 점검 결과 (v10.0.2, 2026-10-04)

점검 방법: `krea2_prompt_studio.py` 3,620줄 중 로직부(구조체, 해결기, 합성기, 린터, 파서, 생성 흐름)를 직접 읽고, 복사본을 Python 3.13으로 실제 실행해 프롬프트 1건을 생성해 확인했다. 어휘 테이블(LOCATIONS, GARMENTS, FABRICS 등)과 메뉴 UI 절은 통독하지 않았다.

## 사용자 실측 (공식 문서보다 우선하는 값)
- LoRA 트리거는 **맨 앞**이 좋다. 현재 구현(`person_prompt`, 첫 토큰으로 출력)을 유지한다.
- **네거티브는 안 먹는다.** 네거티브 입력 기능을 만들지 않고, 프롬프트에 "no X / without X" 식 부정문도 쓰지 않는다.

## A. 확정된 버그 (실행으로 재현)
1. **창문/문이 한 글자씩 쪼개져 출력된다.**
   - 증상: `Windows: a; ; w; i; d; e; ; d; o; u; b; l; e; -; g; l; a; z; e; d; ; w; i; n; d; o; w Doors: a; ; f; l; u; s; h; ...`
   - 원인: `resolve_environment`(1526~)의 `windows`/`doors`는 `choose()`가 돌려준 **문자열**인데, `environment_prompt`(1614~)가 `"; ".join(env.windows)`로 리스트처럼 합친다. `EnvironmentProfile`은 이 둘을 `str`로 선언(220~221줄)하고 있어 타입은 맞지만 합성부가 어긋난다.
   - 영향: 창/문이 있는 실내 장소는 전부 해당. 자가진단은 이걸 못 잡았다.
2. **1인 장면에 2인 문구가 남는다.** `Gaze: looking toward the other person`이 단독 인물 장면에 나왔다. `lint_prompt`의 2인 문구 검사는 "two adult", "two people", "secondary subject"만 봐서 놓친다.
3. **공간 배치 문장이 문법적으로 깨진다.** `foreground at in the far background`, `foreground at near the camera-left edge`처럼 `"{layer} at {position}"`이 이미 전치사를 가진 위치와 부딪힌다(`build_spatial_layout`).
4. **깊이 층 분류가 어색하다.** `charging cable`, `smartphone` 같은 소품이 `Background`로 간다(`background = decor[2:] + practical`). 미드그라운드 슬라이스도 `furniture[max(2, ...) : max(3, len(furniture))]`처럼 의도가 불분명하다.
5. **의상 불일치.** 반바지 + 첼시 부츠 + 소파 + 새벽 같은 조합이 그대로 나온다(의상 해결기가 장소·시간대·계절과 연결되지 않음). 현재는 활동·장소 호환 표(`ACTIVITY_LOCATION_COMPAT`)만 있다.
6. **테마와 활동이 어긋난다.** 테마 "focused study session" + 활동 "working on a laptop"처럼 테마 문구를 그대로 문장에 끼워 넣는다(`Create a natural, realistic scene with {theme_en}`).
7. **Python 3.12 이상 필요.** `clothing_prompt`(1507줄)의 f-string 표현식 안 백슬래시는 3.12 미만에서 SyntaxError다. 사용자 환경(3.13)에서는 문제없지만 README에 요구 버전이 없다.
8. 문장 끝 마침표 누락. 합성 과정의 `scale_rules` 이어붙이기와 `realism`/스타일 문구가 마침표 없이 붙어 `...adult human foreground objects are larger only because...`처럼 이어진다.

## B. 구조적 문제 (공식 가이드와의 충돌) — 업그레이드의 핵심
생성 프롬프트가 **약 750~860단어의 스펙 시트**다. 공식 예시는 한 단락 40~150단어 안팎의 장면 묘사다.

1. **라벨 섹션 형식.** `Hair:`, `Eyes:`, `Walls:`, `Floor:`, `Weight distribution:`, `Support points:`, `Spatial placement:` 같은 필드 라벨이 본문에 그대로 들어간다. 공식 `expansion.txt`는 "한 단락, 불릿·JSON·마크다운 금지, 라벨/래퍼 금지"를 요구한다.
2. **과잉 명세.** 원단 한 벌에 섬유·밀도·섬도·불투명도·두께·무게·질감·광택·신축·뻣뻣함·드레이프·표면반응을 전부 적는다. 공식 규칙 5(입력이 뒷받침하지 않는 디테일을 지어내지 마라)와 반대 방향이다.
3. **메타 지시문이 본문에 섞인다.** `Subject scale lock is enabled...`, `Environment scale lock...`, `Keep all foreground, midground and background elements...`, `Maintain coherent human anatomy...` 같은 모델에게 주는 명령문은 이미지 묘사가 아니다. 린터는 오히려 `subject scale lock` 문구가 **없으면 오류**로 처리한다.
4. **원인은 "옵션 반영 검사"의 설계다.** `prompt_option_coverage`가 해결된 모든 값의 문자열이 최종 프롬프트에 **그대로** 들어갔는지 검사한다. 자연스러운 문장으로 다시 쓰면 검사가 실패하므로, 합성기가 값을 문자열 그대로 이어붙이는 쪽으로 굳어졌다. 업그레이드는 이 검사를 "그대로 포함"에서 "의미 반영"으로 바꿔야 가능하다.
5. **한 장면에 같은 정보가 중복된다.** 같은 가구가 `Furniture`, `Foreground/Midground/Background`, `Spatial placement` 세 군데에 반복된다. 스케일 규칙도 `scale_rules`, `camera_prompt`, 마무리 문장에서 3중으로 나온다.
6. **사용자 예시(`examples/nayoon_sfw_rooftop_sample.txt`, 239단어)가 이미 더 나은 형태다.** 트리거 첫 토큰 + 쉼표 구절 + 짧은 `Lighting:`/`Camera:` + 마무리 한 줄. 이 형식이 이 프로그램 본체에 반영돼 있지 않다.

## C. 유지할 것
- LoRA 트리거 첫 토큰 출력, LoRA `identity` 고정 로직(`lora_profile_for_trigger`, `is_lora_identity_locked`).
- 품질 태그 미사용.
- 한국어 → 영어 번역 모듈 분리 구조(번역 자가 테스트 통과 확인).
- 의상·환경·포즈 해결기의 "충돌 검사 후 수리" 구조(`validate_*`, `_repair_scene`).

## D. 업그레이드 제안 (승인 대기, 순서대로)
1. **버그 수정(A-1~A-8)** — 위험도 낮음. 단위 확인 후 먼저 처리.
2. **프롬프트 합성기 개편(B)** — 가장 큰 효과. 라벨 제거, 한 단락 서술화, 메타 지시문 제거, 중복 제거, 길이 상한. 기존 상세 출력은 "상세 모드"로 남길지 결정 필요.
3. **옵션 반영 검사를 의미 단위로 교체.**
4. **의상–장소–시간대–계절 연동 규칙 추가.**
5. 글자 렌더링(따옴표) 입력 경로 추가 여부는 별도 확인(현재 코드에 없음).
6. 공식 예시 기준 회귀 테스트(길이, 라벨 부재, 한국어 누출, 트리거 첫 토큰).
