# v11 설계안 (2026-10-04, 사용자 요구 반영)

## 0. 사용자 요구 (원문 요지)
1. LoRA 적용 모드에서는 **LoRA identity에 적힌 외형이 기본**. 헤어스타일·액세서리를 바꾸려면 프롬프트에 **강하게** 적어야 한다.
2. 길이는 크게 중요하지 않다. **상세 / 보통 모드**로 나눈다.
3. 의상: 본체에는 **공용 풀**만 둔다. 캐릭터별 **상세 의상 JSON**을 따로 넣는다.
4. 같은 정보를 강화할 때는 **같은 뜻을 다른 표현으로** 쓰고, **정보가 서로 모순되지 않게** 한다.
5. 입력은 한글이다. 번역은 **번역 풀(사전)** 뿐이고 문장 번역기는 없다.
6. UI는 한글. 각 옵션에는 **한글 설명**을 붙인다.

## 1. 프롬프트 형식 (공통)
- 한 단락 서술형. 라벨(`Hair:`, `Walls:`)과 모델용 명령문(`scale lock is enabled`)은 쓰지 않는다.
- 첫 토큰은 LoRA 트리거(사용자 실측으로 확정). 그다음 identity.
- 네거티브/부정문("no X", "without X")은 쓰지 않는다 (사용자 실측: 안 먹음). 원하지 않는 요소는 **원하는 것을 구체적으로 적어 대체**한다.

## 2. 모드
| | 보통 | 상세 |
|---|---|---|
| 인물 | 트리거 + identity 1회 + 표정/포즈 | identity 1회 + 핵심 특징 재진술(다른 표현) + 표정/시선/포즈 |
| 의상 | 한 구절 (색·종류·재질 1~2개) | 의상 JSON의 세부(소재 물성, 디테일, 신발, 소품)를 문장으로 풀어 씀 |
| 장소 | 장소 + 핵심 가구 3~4개 | 층별(전경/중경/배경) 배치와 표면감까지 |
| 조명·카메라 | 1문장 | 2~3문장 |
| 강화 | 없음 | 있음 (3-3 참고) |

길이 상한은 두지 않는다. 사용자가 직접 지정한 항목이 많을수록 자연히 길어진다.

## 2-1. 안전선 (모드와 무관)
- 성인 명시, 의복은 생식기·친밀 부위를 덮는 것으로 가정, 장면은 일상/로맨스 수위. 현재 본체의 범위와 동일하다.

## 3. LoRA 적용 모드

### 3-1. identity가 기본
- LoRA를 지정하면 `loras.json`의 `identity`를 인물 외형의 **유일한 기준**으로 쓴다. 헤어/눈/체형/특징을 새로 랜덤 생성하지 않는다(현행 유지).
- 헤어·액세서리는 사용자가 따로 지정할 때만 바뀐다.

### 3-2. 헤어 (2026-10-04 확정)
- `loras.json`의 LoRA 항목에 `hair` 칸을 따로 둔다. `identity`는 **얼굴·몸(·귀걸이)만** 담는다. 의복은 identity에 넣지 않는다.
- 헤어를 고르지 않으면 `hair` 칸(LoRA 헤어)이 **그대로 고정**된다.
- 헤어를 고르면 LoRA `hair`는 **통째로 빠지고** 새 헤어로 교체된다 (모순 방지).
- `hair` 칸이 없는 기존 LoRA는 종전대로 동작한다(identity 안에 헤어가 있는 경우).
- 새 헤어는 강하게 서술한다. 사용자 작성(D) 방식: 강조어(ALL, very, unmistakable), 같은 사실의 반복, 남는 가능성을 닫는 문장(`nothing falls loose...`), 허용 예외(`only a few short wet wisps`).
- 문장 속 부정 표현(`no X`)은 닫는 문장으로 쓸 수 있다. 별도 네거티브 입력란만 효과가 없다.
- 액세서리: 시그니처(예: 초커)는 LoRA 항목의 `signature_accessories`로 따로 관리한다.

### 3-3. 강화 규칙 (동일 정보, 다른 표현, 무모순)
- 강화 대상: 사용자가 지정/오버라이드한 값, 의상 핵심 아이템, 포즈의 핵심 자세.
- 한 사실에 **표현 변형 세트**를 둔다. 예: "hair worn in a low ponytail" → "the ponytail sits low at the nape" → "a loose low ponytail frames the neck".
- 변형은 같은 사실만 말해야 한다. 변형 세트를 만들 때 값(색, 위치, 길이)은 **한 곳의 원본 값에서 치환**해 만들어 서로 달라질 수 없게 한다.
- 모순 검사: 같은 속성(헤어 길이/스타일, 의상 종류/색, 포즈 상/하체)에 서로 다른 값이 두 번 이상 나오면 생성을 거부하고 수리한다. 현재 `CONFLICT_PATTERNS`를 일반화한다.

## 4. 의상 (2026-10-04 확정: 공용의상 / 로라의상)
- **공용의상**: 본체 공용 풀(`GARMENTS`, `FABRICS` 등). 모든 인물이 쓴다.
- **로라의상**: `krea2_prompt_configs/outfits/lora/<id>.json` (스키마 `krea2-outfit/1`, `scope: "lora_outfit"`).
  특정 캐릭터 전용이 아니다. `character` 칸은 비워 둔다.
- **캐릭터(LoRA)별 의상 목록**: `krea2_prompt_configs/outfits/lists/<이름>.json` (스키마 `krea2-outfit-list/1`).
  `lora_outfits`에 로라의상 id를 적고, `use_common_pool`로 공용의상을 같이 쓸지 정한다.
  `default_source`: `all`(둘 다) / `lora`(로라의상만) / `common`(공용만).
- 현재 등록: `lists/nayoon.json` → `gold_amber_triangle_string_bikini`.
- 나윤 LoRA 사용 시 UI에서 의상 출처를 고른다: 전체 / 로라의상만 / 공용의상만.
- 의상 선택은 `applies_to`(장소, 계절, 활동)와 맞춘다. 수영복처럼 장소가 제한된 의상은 해당 장소에서만 후보가 된다.
- 로라의상의 `locks`(고정 요소)는 보통 모드에서는 구조 요약에, 상세 모드에서는 표현 변형을 바꿔 가며 강화에 쓴다.
- `forbidden_ko`는 프롬프트에 출력하지 않는다(네거티브가 안 먹음). 오버라이드·충돌 검사 전용이다.
- 검증: `python tools/validate_outfits.py [--preview]`.

## 5. 입력과 번역 (번역 풀 기반)
현재 번역 모듈은 **용어 치환기**라서 사전에 없는 말과 조사가 한글로 남는다. 실측:
- `하늘색 오간자 블라우스를 입고 창가에서 책을 읽는 모습` → `sky-blue organza blouse를 입고 by the window에서 책을 읽는 모습`
- `쌍꺼풀 없는 눈과 보조개` → 대부분 미번역

이에 따른 규칙:
1. 자유 문장 입력을 번역하려 하지 않는다. 입력은 **용어 단위 선택**(한글 옵션 + 설명)과 **사전에 있는 용어 매칭**으로 처리한다.
2. 입력에서 사전에 있는 용어는 영어로, **없는 용어는 목록으로 사용자에게 보여주고** 그 자리에서 사전에 추가할지 묻는다(기존 번역 사전 메뉴 재사용). 추가 전에는 프롬프트에 한글을 절대 넣지 않는다(한국어 누출 검사 유지).
3. 조사(을/를/에서/은/는 등)는 용어 매칭 전에 제거한다.
4. 사전에 영어 값이 여러 개일 때 하나만 고르는 규칙은 사용자 사전 > 핵심 > 분야별 순서를 유지한다.

## 6. UI (한글)
- 모든 메뉴와 옵션을 한글로 표시하고, 각 옵션 옆에 한 줄 한글 설명을 붙인다. 예: `생활감 — 정돈돼 있지만 사람이 살고 있는 느낌`.
- 설명 문구는 현재 `FIELD_HELP`(1276줄)를 확장해 옵션 값 단위로 둔다.
- LoRA 관리 메뉴에 `헤어/액세서리 분류 미리보기`(identity 절이 어떻게 분류되는지)를 표시한다.
- 모드 선택(보통/상세)은 생성 전에 고르고 설정에 기억한다.

## 7. 작업 순서

7. 한글 UI 설명 전면 정비
